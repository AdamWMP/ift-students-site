# Instructions for AI agents working on this repo

## Images: always use `next/image`

**Rule (enforced by ESLint):** every image rendered on a page MUST use
`next/image` (`<Image>` component), not raw `<img>` tags.

Why: `next/image` auto-generates responsive sizes, serves modern
formats (WebP/AVIF), lazy-loads off-screen images, and sets explicit
width/height so there's no CLS. It's measurable Lighthouse perf.

How:

```tsx
import Image from 'next/image'

// Static asset in /public — fine, no remote loader config needed.
<Image
  src="/tutors/conor.jpg"
  alt="Conor Whyte"
  width={400}
  height={500}
  className="rounded-lg object-cover"
/>

// For LCP / above-the-fold hero images, add priority + fetchPriority.
<Image
  src="/hero-poster.jpg"
  alt="…"
  fill
  priority
  fetchPriority="high"
/>
```

The ESLint rule `@next/next/no-img-element: "error"` will fail the
build if a raw `<img>` is added. There are two legitimate exemptions
already configured in `.eslintrc.json`:

1. `components/meta-pixel.tsx` — Facebook tracking pixel, must be a
   `<img>` for cross-domain cookie reasons.
2. `components/graduates-banner.tsx` — CSS marquee animation that
   `next/image`'s wrapping `<span>` would break.

Do not extend the exemption list without a similarly hard reason.

## When you add a new image

1. Drop the file in `/public` (or a subfolder like `/public/tutors/`).
2. **Resize before committing**: longer edge should be ~2× the largest
   display size. For a 400-px-wide card, the file should be ≤800 px
   wide. Anything over 2 MB unprocessed is a mistake.
3. Prefer JPG for photographs, PNG only when transparency is required,
   SVG for icons. WebP/AVIF will be auto-generated by `next/image` at
   request time — don't pre-convert.
4. Import via `<Image src="/path/to/file.jpg" …>` with explicit
   width/height (or `fill` when stretching a parent).

## Fonts

The site uses **system fonts** by default. If a Google Font is
introduced later, it MUST be loaded via `next/font/google`, never a
raw `<link href="fonts.googleapis.com/…">` tag — the latter is
render-blocking and was the top mobile-perf issue on the sister
project (`imagepilates.ie`) before May 2026.

## Performance baselines (May 2026, post-Tier 2)

Targets to keep:

- Lighthouse mobile performance ≥ 70
- Lighthouse desktop performance ≥ 90
- No `<img>` outside the two listed exemptions
- No render-blocking external CSS
- Homepage initial JS shipped to mobile < 250 KB gzipped

If a change is going to drop those, mention it in the PR and propose a
mitigation.
